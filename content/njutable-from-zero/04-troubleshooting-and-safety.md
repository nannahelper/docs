# 第 4 章：排错与安全

在线收集工具最常见的问题并不是“不会创建表”，而是链接发错、字段漏加、权限与预期不一致，或者正式收集后才发现附件无法使用。本章给出一套从现象回到原因的检查顺序。

## 1. 先判断问题发生在哪一层

NJUtable 的问题可以分成四层：

| 层级 | 负责什么 | 典型问题 |
|:---|:---|:---|
| 表格 | 保存记录和字段结构 | 缺列、字段类型错误、重复字段 |
| 表单 | 决定填写页面显示什么 | 新字段未添加、顺序不合理 |
| 权限 | 决定谁能访问 | 未登录也能填、登录后仍打不开 |
| 链接 | 把填写者带到正确页面 | 发成后台地址或编辑地址 |

排错时先定位层级，再修改。不要看到问题就重新建一张表，否则很容易出现多个版本和多个链接。

## 2. 常见问题速查

| 现象 | 优先检查 | 处理方法 |
|:---|:---|:---|
| 表单缺少某个字段 | 子表字段 | 确认子表正确，将新增字段加入表单 |
| 下拉框没有选项 | 单选配置 | 进入“编辑单选”，补齐标签 |
| 提交后数据进入错误位置 | 子表选择 | 在表单设置中切换到目标子表 |
| 别人打开后看到后台 | 分享地址 | 重新复制包含 `/dtable/forms/` 的链接 |
| 未登录用户也能访问 | 访问权限 | 选择“仅登录用户”，等待保存后重测 |
| 创建者能填，别人不能填 | 登录或成员权限 | 用普通账号测试，并检查是否存在更细权限 |
| 附件无法上传 | 文件字段和文件本身 | 确认字段类型，尝试更小的常见格式文件 |
| 修改后看不到变化 | 保存和缓存 | 等待保存提示，刷新填写页后重新测试 |

## 3. 不要用真实敏感材料做第一次测试

首次验证时，使用没有隐私内容的测试文本和测试附件。确认权限、字段映射和删除流程都正确后，再开始正式收集。

如果收集的内容包含个人信息或敏感材料，应至少明确：

- 收集目的和必要字段。
- 谁可以查看后台数据。
- 链接可以转发到什么范围。
- 材料保留到什么时候。
- 填写错误后如何更正或删除。

“仅登录用户”不能替代完整的权限和数据管理方案。

## 4. 正式发布前检查表

### 表格

- [ ] 表名能够说明用途。
- [ ] 字段名称没有歧义。
- [ ] 字段类型与内容匹配。
- [ ] 单选和多选的选择符合实际需求。

### 表单

- [ ] 选择了正确子表。
- [ ] 所需字段全部加入填写页。
- [ ] 字段顺序和帮助文字清楚。
- [ ] 文件要求已经写明。

### 权限与链接

- [ ] 访问权限符合收集范围。
- [ ] 转发的是填写页，不是后台或编辑页。
- [ ] 使用无痕窗口或普通账号测试成功。
- [ ] 测试记录已经清理或标记。

## 5. 最终实践

创建一张用于收集活动材料的表，至少包含：

- 一个文本字段。
- 一个单选字段及不少于两个选项。
- 一个文件字段。
- 一个传统表单。
- 仅登录用户访问限制。

然后用普通填写者视角提交一条测试记录，回到后台核对每个字段，最后把填写链接和一段完整说明保存到自己的工作记录中。

## 一句话复述

表格定义数据，表单负责填写，权限控制访问，正确链接把填写者带到正确页面；正式发布前必须从填写者视角完成一次闭环测试。
