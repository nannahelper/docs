# 第 15 章：在看不见的数据上做深度学习：联邦学习

前面的训练过程默认数据都能放到同一台机器：收集样本、集中训练、保存模型。但手机输入、医院记录、企业日志等数据可能不能或不应该离开本地。联邦学习讨论的是另一个问题：能不能让模型到数据所在的位置学习，只交换必要的模型更新？

## 本章要解决的问题

联邦学习不是“把数据加密后上传再训练”的同义词，也不是“只要数据不出设备就绝对安全”。它是一种训练组织方式，核心边界是：

```text
服务器下发模型 → 客户端用本地数据训练 → 客户端上传更新 → 服务器聚合 → 开始下一轮
```

本章完成后，你应该能够：

- 画出一轮联邦平均（FedAvg）的参与者和数据流。
- 用公式解释多个客户端参数如何聚合。
- 说明非独立同分布数据为什么会影响训练。
- 区分联邦学习、集中式训练、分布式训练和隐私保护技术。
- 指出联邦学习仍可能泄露什么，以及需要哪些额外防护。

## 1. 从集中式训练到本地训练

集中式训练把所有样本写成：

```text
客户端 A 的数据 + 客户端 B 的数据 + 客户端 C 的数据 → 服务器训练
```

联邦学习则让原始数据留在本地：

```text
                 ┌─ 客户端 A：本地训练 ─┐
服务器模型 ──────┼─ 客户端 B：本地训练 ─┼─→ 聚合后的新模型
                 └─ 客户端 C：本地训练 ─┘
                 原始数据不集中上传
```

服务器仍然知道全局模型参数和客户端更新，客户端也仍然需要信任协议、软件和设备环境。因此，“数据不直接上传”只是边界的一部分，不是完整的隐私保证。

## 2. FedAvg 的核心公式

第 $r$ 轮开始时，服务器有全局参数 $w^{(r)}$。选出若干客户端后，每个客户端拿到一份副本，在自己的数据上训练得到 $w_k^{(r+1)}$。服务器按照本地样本数加权平均：

$$
w^{(r+1)}=\sum_{k=1}^{K}\frac{n_k}{\sum_jn_j}w_k^{(r+1)}
$$

其中 `n_k` 是第 `k` 个客户端参与训练的样本数。样本多的客户端权重更大，避免一个只有少量样本的客户端对全局模型产生不成比例的影响。

如果所有客户端的数据分布类似，FedAvg 往往更容易稳定；如果某个客户端只看到某一类数据，简单平均可能产生较大漂移，这就是非独立同分布（non-IID）问题。

## 3. 一个可手算的聚合例子

假设服务器初始只有两个参数：

```text
w = [1.0, 2.0]
```

两个客户端本地训练后得到：

```text
客户端 A：w_A = [1.4, 1.8]，样本数 3
客户端 B：w_B = [0.8, 2.4]，样本数 1
```

则：

$$
w_{new}=\frac{3}{4}[1.4,1.8]+\frac{1}{4}[0.8,2.4]=[1.25,1.95]
$$

手算时要注意：聚合的是同一模型的同一参数位置，而不是把客户端的预测结果拼接起来。模型参数、梯度、预测和原始样本是不同层次的对象。

## 4. NumPy 模拟一轮 FedAvg

可以先用不涉及真实隐私数据的数组模拟聚合：

```python
import numpy as np


def fedavg(client_weights, client_sizes):
    total = sum(client_sizes)
    result = np.zeros_like(client_weights[0], dtype=float)
    for weights, size in zip(client_weights, client_sizes):
        result += weights * (size / total)
    return result


clients = [
    np.array([1.4, 1.8]),
    np.array([0.8, 2.4]),
]
print(fedavg(clients, [3, 1]))
```

扩展实验时可以让每个客户端使用不同的线性回归数据，执行“本地多步 SGD → 上传参数 → FedAvg → 下一轮”。必须同时记录：

- 每个客户端的样本数。
- 本地训练步数和学习率。
- 每轮聚合前后的参数。
- 全局验证集损失，而不是只看某一个客户端的损失。

## 5. 联邦学习不等于自动隐私

即使原始数据没有离开客户端，模型更新也可能包含关于本地数据的信息。一个不诚实的服务器、被攻击的客户端或不安全的传输链路，都可能造成风险。因此实际系统常组合使用：

- **安全聚合**：服务器只能看到多个客户端更新的合计，尽量看不到单个更新。
- **差分隐私**：在更新或统计量中加入经过控制的噪声，限制单条样本的影响。
- **传输加密与身份认证**：保护更新在传输过程中的机密性和完整性。
- **客户端筛选与异常检测**：减少恶意更新或失控客户端对模型的影响。
- **审计和退出机制**：明确谁可以参与、数据如何删除、模型如何回滚。

这些技术各有代价：噪声可能降低准确率，安全聚合会增加协议复杂度，客户端设备的算力和网络也不稳定。设计时必须同时谈准确率、通信、功耗、延迟和隐私目标。

## 6. 与相近概念区分

| 概念 | 数据位置 | 主要目标 | 与联邦学习的关系 |
|:---|:---|:---|:---|
| 集中式训练 | 集中到训练服务器 | 简化训练和提高吞吐 | 数据直接集中 |
| 分布式训练 | 多台机器共同处理同一训练任务 | 加速训练 | 数据可以集中在集群内 |
| 联邦学习 | 留在多个客户端或机构 | 在数据边界内协作训练 | 重点是数据不集中 |
| 差分隐私 | 数据或统计输出处加入噪声 | 限制个体可识别性 | 可作为联邦学习的额外保护 |
| 安全聚合 | 服务器只见聚合结果 | 隐藏单个客户端更新 | 可作为联邦学习的协议组件 |

## 8. 常见错误

- **把参数平均和梯度平均混为一谈**：二者可以在特定算法下建立联系，但实现和解释不能混用。
- **忽略客户端样本量**：直接等权平均可能让小数据客户端影响过大。
- **默认所有客户端数据同分布**：真实设备、医院和组织之间往往存在明显偏差。
- **声称“绝对隐私”**：联邦学习降低了原始数据集中传输的需求，但不自动消除更新泄露、恶意客户端和服务器风险。
- **只测平均准确率**：还要看各客户端表现、公平性、通信失败和最差客户端结果。
