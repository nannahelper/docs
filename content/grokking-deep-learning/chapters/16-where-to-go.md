# 第 16 章：往哪里去：简要指引

这一章不是再引入一个新的网络结构，而是帮助你把前 15 章放回一张地图中：从一个权重的预测和更新，走到多层网络、卷积、词嵌入、循环层、LSTM、框架和联邦学习。读完本书的目标不是记住所有 API，而是看到一个新模型时，知道应该从输入、状态、损失、梯度和验证哪些角度拆解它。

## 本章要解决的问题

学完一套入门材料后，最容易出现两种情况：

- 只会继续寻找下一篇“更简单的教程”，没有真正完成一个可验证的项目。
- 直接跳到最热门的模型，却无法解释数据、形状、损失和训练失败。

本章把“下一步”改成可执行的选择：先复述核心闭环，再根据兴趣选择方向，最后用一个小项目证明自己真的会用。

## 1. 把全书压缩成一条链

可以用下面的链条复述本书：

```text
输入数据
  ↓
前向传播：参数如何产生预测
  ↓
损失函数：预测错了多少
  ↓
反向传播：每个参数应该负责多少错误
  ↓
优化器：参数如何更新
  ↓
验证：模型能否在没见过的数据上工作
  ↓
结构扩展：CNN、词嵌入、RNN、LSTM、框架、联邦学习
```

如果一个新模型无法放回这条链，先不要急着背结构图。先问：它的输入是什么？输出是什么？参数在哪里？损失如何定义？梯度从哪里来？训练和推理有什么区别？

## 2. 六个方向，选择一个继续

| 方向 | 适合的问题 | 建议先补的内容 | 第一个小项目 |
|:---|:---|:---|:---|
| 机器学习基础 | 想理解模型为何有效 | 概率、线性代数、微积分、统计 | 从零实现线性回归并做验证 |
| 计算机视觉 | 想处理图片和视频 | CNN、数据增强、评价指标 | 用小数据集完成图像分类 |
| NLP 与大语言模型 | 想理解文本和生成 | 词嵌入、注意力、Transformer | 做一个可解释的文本分类器 |
| 深度学习工程 | 想把模型稳定跑起来 | PyTorch、数据管道、实验管理 | 训练脚本、配置文件和检查点 |
| 隐私与分布式学习 | 关心数据边界和协作 | 联邦学习、安全、系统设计 | 模拟多个客户端的 FedAvg |
| 理论与研究 | 想读论文和改进方法 | 优化、泛化、表示学习 | 复现实验并写失败分析 |

不要把表格当成必须全部完成的清单。选择一个方向做出小产出，再回头补最影响当前问题的数学和工程知识。

## 3. 从 NumPy 过渡到 PyTorch

第 13 章的最小框架和 PyTorch 有直接对应关系：

| 本课程手写内容 | PyTorch 中的对应物 |
|:---|:---|
| `Linear` 类 | `torch.nn.Linear` |
| 层的 `parameters()` | `model.parameters()` |
| 手写 `backward` | 自动求导得到的 `.grad` |
| `SGD.step()` | `torch.optim.SGD.step()` |
| `zero_grad()` | `optimizer.zero_grad()` |
| 手写批量循环 | `DataLoader` 加训练循环 |
| 手写损失 | `torch.nn` 中的损失函数 |

过渡时不要只把 NumPy 代码全部替换成 API。建议保留一个手写版本作为对照，至少能解释框架生成的梯度形状和参数更新方向。

## 4. 一个能证明理解的项目

项目不需要大，应该有清楚的输入、目标和验收标准。可以按下面的结构完成：


1. 写问题定义：模型要预测什么，不预测什么？
2. 建立最小数据集：先能在少量样本上过拟合，证明代码链路正确。
3. 写形状表：输入、标签、每层输出和损失的形状。
4. 记录基线：随机预测或简单规则的表现是什么？
5. 训练并保存配置：随机种子、学习率、批量大小和模型结构。
6. 分开训练集和验证集，解释两者表现的差异。
7. 故意制造一次失败：学习率过大、标签错位、形状错误或数据泄漏。
8. 写复盘：哪些现象能由公式解释，哪些问题还没有解决？

一个项目只有“最终准确率”是不够的。真正有价值的产出应该让别人能够复现，并让你能够解释一次失败。

## 5. 数学补课的最小清单

不需要先把所有数学学完才开始写代码，但遇到下面的概念时要逐步补上：

- 向量、矩阵乘法和转置：解决形状和线性层问题。
- 导数和链式法则：解决梯度方向和反向传播问题。
- 概率分布和对数：解决 Softmax、交叉熵和分类输出问题。
- 均值、方差和抽样：解决批量、正则化和泛化问题。
- 优化和约束：解决学习率、收敛和训练不稳定问题。

每次补数学时都配一个已经运行过的小代码，不要把公式和实验完全分开。

## 6. 全书最终自测

尝试不打开章节页面回答：

1. 一个输入经过线性层后，输出形状如何确定？
2. 梯度下降为什么要沿负梯度方向更新？
3. 多层网络的梯度为什么需要链式法则？
4. 训练损失下降但验证损失上升说明了什么？
5. CNN 的局部连接和权重共享解决了什么问题？
6. 词嵌入为什么比直接使用词编号更合理？
7. RNN 的隐藏状态和 LSTM 的细胞状态分别做什么？
8. 为什么要把层、损失和优化器分开组织？
9. FedAvg 聚合的是什么，联邦学习又没有自动解决什么？
10. 如果实验结果不对，你会按什么顺序检查数据、形状、公式、梯度和评估？

答不出的问题就回到对应章节，不要把“看过页面”当成“掌握概念”。可以在[问题日志](../questions.md)记录自己的猜测和验证结果。

## 7. 推荐的下一步顺序

对大多数刚完成本课程的学习者，建议按下面顺序推进：

```text
完成第 3–6 章最小实现
  → 用第 13 章的层接口重构
  → 用 PyTorch 重写同一个小项目
  → 选择 CNN 或 NLP 方向
  → 加入验证、实验记录和错误分析
```

小助手还推荐各位根据[谷歌机器学习速成课程](https://developers.google.com/machine-learning/crash-course?hl=zh-cn)再过一遍，把本书的直觉和更系统的机器学习概念互相对照。
