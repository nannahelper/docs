# 第 3 章：来源与证据 — 谁亲眼见过这件事

## 📋 本章概览

| 项目 | 内容 |
|:---|:---|
| 学习时长 | 60 分钟 |
| 核心概念 | 一手来源、二手来源、作者、日期、版本、证据 |
| 核心比喻 | 证人和原始记录 |
| 实践任务 | 给三个来源做可信度标注 |

官方文档、原始论文、项目仓库和原始数据通常更接近事实；博客、视频和帖子适合帮助理解，但要回到一手来源核对。来源可靠不等于结论适用于你的版本。

## 3.1 一手、二手和三手来源

一手来源是直接发布事实的人或机构，例如软件官方文档、更新日志、论文原文、政府公告和原始数据；二手来源是别人对它的解释；三手来源可能只是转发。先用易懂的二手材料理解，再回一手来源确认。

## 3.2 读页面身份信息

打开页面后找作者或机构、发布日期、更新时间、适用版本、引用链接和联系方式。页面没有作者或日期不代表一定错误，但意味着你需要更多来源交叉检查。

## 3.3 “有引用”不等于支持结论

点击引用链接，读它实际说了什么。一个来源可能只支持“功能存在”，不支持“功能在所有版本可用”；可能只描述实验结果，不支持“对所有人都有效”。把结论范围写小，比写得漂亮更可靠。

## ✅ 验证步骤

为三个来源记录作者或机构、发布时间、更新时间、适用版本、原始证据和可能的利益关系；最后标注“可直接支持 / 部分支持 / 只能提供线索”。

## ❌ 常见情况

| 现象 | 处理方法 |
|:---|:---|
| 页面写“最新”但没有日期 | 找更新日志或版本页面 |
| 博客说官方已经宣布 | 打开官方公告核对原文 |
| 视频讲得很清楚 | 记下关键说法，再找书面来源 |
| 两个来源结论不同 | 比较版本、样本、时间和定义 |

## 📝 本章总结

- 来源的身份、日期和适用范围都重要。
- 引用要支持具体结论，不能只装饰在段尾。
- 不确定时降低结论强度，明确写“尚未确认”。

## ✏️ 课后练习

找一条“某软件最新功能”的说法，核对官方更新日志或文档，写下它在哪个版本、什么日期被确认。
