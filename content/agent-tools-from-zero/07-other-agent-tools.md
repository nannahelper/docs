# 第 7 章：其他 Agent 工具与协作方式 — 按任务选择工作台

## 📋 本章概览

| 项目 | 内容 |
|:---|:---|
| 学习时长 | 8 分钟 |
| 核心概念 | GUI、CLI、IDE、上下文、权限、可审计性 |
| 核心比喻 | 不同 Agent 是不同工作台，工具越多越要看安全护栏 |
| 实践任务 | 为同一个任务选择工具并写出授权清单 |
| 难度等级 | ★★★☆☆ |

## 工具不同，协作方式也会不同

GUI、CLI、IDE 扩展和远程工作台并不是简单的外观差异。GUI 往往更容易看到会话和权限提示，CLI 更适合远程与重复执行，IDE 能让 Agent 贴近代码上下文，但也可能让它更容易接触整个工作区。选择入口时，要把便利性和可见性、可审计性一起考虑。

同一个任务可以在不同工具中完成，但授权清单不应被工具名称替代。无论使用哪一种，都要明确输入来自哪里、结果写到哪里、哪些动作需要确认、出错后怎样回滚。能说清这些，才是在使用工具，而不是被工具的默认行为带着走。

## 7.1 常见工具的入口差异

| 工具 | 入口 | 更适合 | 先确认 |
|:---|:---|:---|:---|
| OpenCode Desktop | GUI | 可视化项目、会话和权限管理 | Provider、模型、工作区 |
| OpenCode CLI | 终端 | 远程主机、脚本、可复现命令 | 认证、命令范围、日志 |
| Claude Code | CLI | 终端内的代码协作 | 账号、模型、工具权限和费用 |
| GitHub Copilot CLI | CLI | GitHub 生态和命令行问答 | 订阅、数据流向和执行确认 |
| Cursor / Cline | IDE 扩展 | 编辑器内持续开发 | 工作区权限、扩展来源、网络访问 |

## 7.2 用任务矩阵做选择

| 问题 | 建议入口 |
|:---|:---|
| 只想解释一个报错 | GUI 或 CLI 均可，优先只读模式 |
| 要在远程服务器复现 | CLI，限制目录和命令 |
| 要反复编辑同一项目 | IDE 或 Desktop，保留 Git 分支和 diff |
| 要批量执行相同任务 | CLI 脚本，先在一个样本上验证 |
| 需要浏览器、外部 API 或 MCP | 先列出数据流和权限，再决定是否启用 |

## 7.3 协作交付格式

无论使用哪种工具，都要求 Agent 输出：

```text
任务目标：
实际读取/执行：
发现的证据：
修改的文件：
仍然不确定：
人工验收命令：
回滚方式：
```

## ✅ 验证步骤

为“解释一个失败测试”任务分别选择 GUI 和 CLI，写下选择理由、允许的文件、允许的命令和停止条件。不能说明边界时，不启动 Agent。

## 📝 本章总结

- Agent 的差异不只在模型，也在上下文入口、工具权限和审计能力。
- 任务越自动化，越需要小范围试运行和可回滚结果。
- 工具选型应服务于任务，不应由排行榜或宣传语替你决策。
