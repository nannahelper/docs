## 6.1 先向小黄鸭说明任务

Agent 不是读心术。完全不会编程时，也可以按下面的顺序把任务说清楚：

1. **目标**：我最终想得到什么？例如“知道测试为什么失败”。
2. **范围**：允许读取哪些文件？例如“只读 `src/` 和 `tests/`”。
3. **现象**：我看到了什么？贴出完整报错和复现命令。
4. **限制**：不修改、不删除、不联网、不安装依赖，哪些动作必须先问我？
5. **产出**：我要根因、证据、候选方案和验证命令，而不是一句“已经修好了”。

可以直接复制这张任务卡：

```text
目标：请解释项目中一个具体问题
项目目录：请填写绝对路径
允许读取：请列出文件或目录
允许执行：只运行这条复现命令
禁止操作：修改、删除、安装、联网、提交和推送
已知现象：粘贴完整输出
请先复述目标和边界，再开始只读分析；缺少信息时先提问。
最终输出：事实证据、可能根因、仍不确定的地方、下一步验证命令。
```

## 6.2 GUI：一步一步完成第一次只读任务

1. 创建一个不含密钥和隐私文件的练习项目。
2. 打开 OpenCode Desktop，选择这个项目目录。
3. 确认工作区不是生产项目，检查 `git status` 是否干净。
4. 连接已准备好的 DeepSeek Provider，选择当前可用模型。
5. 粘贴上面的任务卡，把“禁止操作”保留在消息中。
6. 阅读 Agent 的计划；如果它提出修改或执行额外命令，先拒绝并要求解释原因。
7. 查看它引用的文件和命令输出，自己在终端复现关键证据。
8. 执行 `git diff`，确认只读任务没有产生改动。

## 6.3 CLI：用同一张任务卡复现

在项目目录运行：

```bash
opencode
```

进入会话后粘贴任务卡。也可以先用命令行传入一次性任务：

```bash
opencode run "只读分析当前项目的测试失败原因；不要修改文件、安装依赖或执行未授权命令。先列出计划。"
```

如果模型或 Provider 尚未配置，先使用 `/connect` 和 `/models` 完成连接与选择；涉及认证时不要把 API Key 写进命令历史或提交到仓库。

## 6.4 读懂 Agent 的结果

把结果分成四类：

| 类型 | 你要检查什么 |
|:---|:---|
| 事实 | 是否有文件路径、命令和原始输出支持 |
| 推断 | 是否明确说明“可能”而不是伪装成确定结论 |
| 建议 | 是否可在练习项目中验证，副作用是什么 |
| 未知 | 是否列出缺失信息和停止原因 |

## ✅ 验证步骤

用 GUI 和 CLI 完成同一个只读问题；保存任务卡、Agent 输出、关键命令和 `git status`。只有人工确认根因后，才创建第二个任务授权最小修改。

## 📝 本章总结

- 小黄鸭原则让任务先变得可解释，Agent 才有可靠上下文。
- 第一次使用 Agent 从只读任务开始，先验收证据，再谈修改。
- GUI 与 CLI 可以使用同一套任务卡，区别只是交互入口。

## ✏️ 课后练习

1. 把“帮我修好这个项目”改写成一张带范围和停止边界的任务卡。
2. 让 Agent 先复述任务；如果复述遗漏了禁止操作，不要开始执行。
