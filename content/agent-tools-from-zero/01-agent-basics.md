# 第 1 章：Agent 是什么 — 一个有工具权限的协作者

## 📋 本章概览

| 项目 | 内容 |
|:---|:---|
| 学习时长 | 45 分钟 |
| 核心概念 | 模型、上下文、工具、权限、任务循环 |
| 核心比喻 | Agent 像一个能读文件、调用工具但必须遵守工作证权限的协作者 |
| 实践任务 | 为一个小任务写出范围、输入、权限和验收标准 |
| 难度等级 | ★☆☆☆☆ |

## 1.1 从聊天到任务循环

普通聊天主要产生文本；Agent 还会根据任务读取文件、调用命令、修改内容或请求外部服务。一个典型循环是：

1. 理解目标和上下文。
2. 制定下一步行动。
3. 请求或执行工具调用。
4. 查看结果并修正计划。
5. 交付变更和验证证据。

## 1.2 五个核心部件

| 部件 | 作用 | 例子 |
|:---|:---|:---|
| 模型 | 生成计划和回答 | DeepSeek V4 Pro |
| 上下文 | 提供项目背景 | 当前目录、README、相关源码 |
| 工具 | 连接外部能力 | 读取、编辑、Shell、Git |
| 权限 | 限制能做什么 | 只读、编辑、执行、联网 |
| 验收 | 判断是否完成 | 测试、构建、Diff、人工确认 |

!!! info "Agent 不等于自动批准"
    Agent 能提出或执行动作，不代表动作一定正确。删除文件、安装依赖、运行脚本和推送代码都应该有明确范围和可回滚方案。

## 1.3 写一份可执行任务单

```text
目标：为 README 增加安装说明
范围：只修改 README.md
允许：读取 README，编辑 README，运行 Markdown 检查
禁止：删除文件，修改依赖，推送远程仓库
验收：检查 diff，确认构建成功，确认无密钥进入文件
```

## ✅ 验证步骤

为自己的测试项目写一份任务单，至少包含目标、范围、允许、禁止和验收五项。删除“禁止”或“验收”项后，说明任务风险会如何增加。

## 📝 本章总结

- Agent 是模型、上下文、工具和权限组成的任务系统。
- 任务越具体，Agent 越容易产生可验证结果。
- 验收标准不是附加项，而是任务的一部分。

## ✏️ 课后练习

2. 为“新增一个功能”写一份包含回滚方案的任务单。
