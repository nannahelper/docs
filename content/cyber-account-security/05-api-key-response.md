# 第 5 章：API Key 与泄露响应 — 密钥泄露后先止血

## 📋 本章概览

| 项目 | 内容 |
|:---|:---|
| 学习时长 | 25 分钟 |
| 核心概念 | API Key、环境变量、撤销、轮换、账单 |
| 核心比喻 | 一次性门卡 |
| 实践任务 | 写一份密钥泄露应急卡 |

API Key 是“代表你调用服务的凭证”，不要写进源码、截图、Issue、聊天记录或公开仓库。环境变量能减少误提交，但不是绝对保险。

## 5.1 泄露后的顺序

1. 立即在服务商后台撤销或禁用旧 Key。
2. 创建新 Key 并更新本地配置。
3. 检查调用记录、费用和权限范围。
4. 从 Git 历史和公开页面清理泄露内容。
5. 记录时间线，必要时联系服务商。

## ✅ 结课任务

写一张不含真实密钥的应急卡，包含服务商后台入口、撤销位置、账单检查位置和联系渠道。
