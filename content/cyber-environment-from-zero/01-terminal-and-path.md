## 先理解终端在替你做什么

终端不是“更酷的文件管理器”，而是一个把文字命令交给操作系统执行的入口。你输入的每个词都有作用：有的选择程序，有的指定文件，有的改变选项。因为它不会自动替你猜意图，所以命令行操作更适合建立可重复的步骤，也更需要在执行前看清当前目录和命令目标。

PATH 可以理解为系统手里的地址簿。你输入 `git` 时，系统会按地址簿逐个目录寻找它；找到多个版本时，顺序还会影响实际调用哪一个。理解这个过程后，“明明安装了却提示找不到”就不再像玄学，而是一个可以检查路径、版本和终端状态的问题。

## 1.1 认识当前目录

终端不是“黑色窗口版文件管理器”，而是直接向操作系统发出命令的入口。先确认当前目录：

=== "Windows PowerShell"
    ```powershell
    Get-Location
    Get-ChildItem
    ```

=== "macOS / Linux"
    ```bash
    pwd
    ls
    ```

## 1.2 认识 PATH

当你输入 `python` 或 `git` 时，系统会按 PATH 中的目录顺序寻找可执行文件：

=== "Windows PowerShell"
    ```powershell
    $env:Path -split ';'
    Get-Command python -ErrorAction SilentlyContinue
    ```

=== "macOS / Linux"
    ```bash
    printf '%s\n' "$PATH" | tr ':' '\n'
    command -v python3
    ```

!!! warning "不要随意覆盖 PATH"
    安装程序通常会追加 PATH。不要把整条 PATH 替换成一个新值，否则可能导致系统命令和已有工具全部找不到。

## 1.3 查看退出码

命令通常通过退出码告诉调用者成功或失败：

=== "Windows PowerShell"
    ```powershell
    Get-Command git
    $LASTEXITCODE
    ```

=== "macOS / Linux"
    ```bash
    command -v git
    echo $?
    ```

## ✅ 验证步骤

记录当前目录、系统版本、Python 路径和 Git 版本。每一项都要能从命令行得到明确结果；命令不存在时，记录完整错误而不是只写“不能用”。

## 📝 本章总结

- 当前目录决定相对路径的起点。
- PATH 决定系统从哪里寻找命令。
- 退出码是脚本判断成功或失败的重要信号。
