## 7.1 小黄鸭原则是什么

想象你要向一只不会回答的小黄鸭解释问题。你不能说“它就是不行”，而要说清楚：我要做什么、我在哪个目录、我输入了什么、电脑原样返回了什么、我原本期待什么。

这不是卖萌，而是一种把模糊感觉变成证据链的排错方法。很多问题在你逐句解释时就已经暴露出原因：目录错了、命令拼错了、终端没有重启，或者你把警告误认为失败。

## 7.2 完全零基础的操作步骤

每次只做一步，结果不同就停下来记录：

1. 打开 PowerShell 或终端，不要同时打开多个窗口。
2. 复制一条命令，例如 `python --version`，按回车。
3. 等命令结束，完整复制输出，不要只截取最后一行。
4. 记录当前目录：PowerShell 执行 `Get-Location`，macOS/Linux 执行 `pwd`。
5. 对照“我想看到什么”：版本号、文件列表，还是一条成功提示？
6. 如果结果不同，先不安装、不删除、不修改 PATH，进入下一节写问题卡片。

## 7.3 小黄鸭问题卡片

复制下面的模板，连同完整错误输出一起保存：

```text
我想完成：例如检查 Python 是否安装
当前系统和终端：Windows 11 + PowerShell
当前目录：C:\Users\me\hello-node
我执行的原命令：python --version
实际输出：请粘贴完整内容
我期望看到：Python 版本号
我已经尝试：只执行过这一条命令
限制：不删除文件、不执行未知远程脚本
下一步：请先解释可能原因和检查命令，不要直接修改系统
```

## 7.4 一个可照抄的排错案例

现象：`python --version` 提示“不是内部或外部命令”。按顺序检查：

```powershell
Get-Command python -ErrorAction SilentlyContinue
py --version
where.exe python
```

如果 `py --version` 成功而 `python` 失败，说明 Python 可能已安装但命令别名或 PATH 未配置一致。此时记录结果，重新打开终端，再查看第 1 章的 PATH 说明；不要立刻修改系统变量。

## 7.5 什么时候必须停止

遇到以下情况先停止并询问有经验的人：命令要求删除目录、覆盖配置、关闭安全防护、输入管理员密码、上传项目文件或暴露 API Key。排错的目标是缩小问题，不是为了“让它动起来”而牺牲数据和权限。

## ✅ 验证步骤

任选一个命令，完成一张问题卡片；让另一位同学只看卡片，能复现你的检查顺序并判断下一步。若不能，说明描述还缺少系统、目录、命令或完整输出。

## 📝 本章总结

- 小黄鸭原则要求先把现象说完整，再提出解决方案。
- 最小复现一次只改变一个变量，结果更容易解释。
- 涉及删除、权限、密钥和外传数据时，停止边界优先于速度。
