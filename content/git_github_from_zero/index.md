# Git 与 GitHub 团队协作指南

Git 负责记录项目在本地的每一次重要变化，GitHub 负责让代码、问题和协作流程能够在云端共享。本教程从安装和第一次提交开始，逐步走到分支、远程仓库、代码审查、冲突处理和项目协同。

## 📖 关于本教程

| 项目 | 内容 |
|:---|:---|
| 适合人群 | 第一次接触版本控制，或想把个人项目放到 GitHub 的学习者 |
| 预计时长 | 约 3–4 小时（按章节跟做和验证估算） |
| 适用版本 | Git 当前稳定版；GitHub 网页界面以当前版本为准 |
| 维护状态 | 维护中 |
| 最后更新 | 2026-08-14 |
| 反馈入口 | [GitHub Issues](https://github.com/nannahelper/docs/issues) |

## 🎯 学习目标

- 能在本地创建仓库、提交变更并查看历史。
- 能使用 `.gitignore` 排除虚拟环境、构建产物和密钥。
- 能通过分支、合并和远程仓库管理并行开发。
- 能处理常见合并冲突，并在提交前检查 Diff。
- 能使用 GitHub Issues、Projects 和 Discussions 支持团队协作。

## 📋 前置要求

- 会使用文件管理器和终端进行基本的复制、切换目录操作。
- 有一个不含真实密钥的练习项目。
- 不要求提前会编程，但需要愿意跟着命令逐步验证结果。

## 🚀 开始前准备

先准备一个练习目录，里面放一两个可以随时修改的文本或代码文件。第一次练习不要把密码、API Key、个人隐私或重要项目直接提交到仓库。

## ✅ 完成标准

你能独立完成“创建仓库 → 提交变更 → 创建分支 → 合并 → 推送 GitHub → 检查 Diff”的完整流程，并能解释每一步出现问题时应该查看什么证据。
