# 第 6 章：网页问题排查 — 沿着快递单找问题

## 📋 本章概览

| 项目 | 内容 |
|:---|:---|
| 学习时长 | 65 分钟 |
| 核心概念 | 现象、范围、状态码、版本、隐私、复现 |
| 核心比喻 | 快递追踪单 |
| 实践任务 | 写一份可交给老师或客服的网页故障记录 |

排查顺序是收集证据，不是反复刷新：确认网址和权限，确认其他网页是否正常，查看请求状态码，再看 Console 错误和响应内容。

## 6.1 先判断问题范围

回答四个问题：只有一个网站打不开，还是所有网站都打不开？只有一个浏览器有问题，还是其他浏览器也一样？只有一个设备有问题，还是同一网络中的设备都一样？登录前和登录后是否不同？

## 6.2 记录一次下载失败

写下网址、时间、文件名、浏览器和版本、状态码、文件大小、是否能访问其他网页，以及完整错误提示。不要把带登录状态的完整链接发给别人；分享前删除参数或改用公开复现地址。

## 6.3 一次只改变一个条件

先在当前浏览器重试一次，再用隐私窗口测试；如果仍然失败，再换一个可信浏览器或网络。每改变一个条件就记录结果，不要同时清缓存、换网络、改 DNS 和重装浏览器，否则无法判断原因。

## 6.4 什么时候停止

遇到要求安装陌生插件、运行命令、关闭安全软件、输入 API Key 或支付信息的“修复页面”，立即停止。网页问题不值得用账号和电脑安全去交换。

## ✅ 验证步骤

模拟记录一次公开网页故障：网址、时间、范围、浏览器、Network 状态码、Console 现象、你实际尝试过的动作和结果。让另一位同学只看记录，判断能否复现。

## 📝 本章总结

- 先判断范围，再选择检查工具。
- 一次只改变一个条件，结果才有意义。
- 求助时去掉账号、Cookie、Token、邮箱和私人参数。

## 🎉 结课任务

提交一页“网页观察报告”：一个网址的组成、一次请求记录、一个状态码解释、Cookie/缓存/下载的区别和一份安全故障记录。完成后进入[账号安全与隐私](../cyber-account-security/index.md)。
