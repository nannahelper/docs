# 第 2 章：网址与 DNS — 浏览器先要找到门

## 📋 本章概览

| 项目 | 内容 |
|:---|:---|
| 学习时长 | 15 分钟 |
| 核心概念 | 协议、域名、端口、路径、参数、DNS |
| 核心比喻 | 通讯录、门牌号和房间号 |
| 实践任务 | 拆解并比较三个网址 |

网址像地址：协议说明如何联系，域名像小区名称，端口像入口，路径像楼栋和房间，参数像给前台的额外说明。

```text
https://example.com:443/docs/start?lang=zh
协议       域名       端口 路径       参数
```

## 2.1 域名和 IP

人更容易记住域名，电脑在网络中通常需要 IP 地址。DNS 像通讯录，负责把域名找到对应地址。DNS 能正常工作，只说明“找到了门”，不保证门后的网站一定正常。

## 2.2 网址中的安全信号

`https://` 表示浏览器与网站之间使用了加密连接，但它不自动证明网站值得信任。真正要看的还有完整域名、拼写、登录场景和链接来源。`example.com.evil.test` 的真正域名不是 `example.com`，而是最后靠近结尾的注册域名。

## 2.3 观察跳转

从一个可信入口打开网页，观察地址栏是否跳转到另一个域名。跳转可能是正常的登录或内容分发，也可能是钓鱼。第一次遇到陌生域名时，不要输入密码，先从官方网站重新进入。

## ✅ 验证步骤

从三个公开网址中标出协议、域名、路径和参数；比较一个短网址和展开后的真实网址；说明为什么“有 HTTPS”不能替代核对域名。

## ❌ 常见情况

| 现象 | 解释 |
|:---|:---|
| 域名拼写很像官方 | 逐字核对，不要只看 Logo |
| 页面一直加载 | 可能是网络、DNS、服务器或浏览器问题 |
| 域名能打开但页面报错 | 找到门不等于房间里的服务正常 |
| 地址栏参数很长 | 可能包含筛选或会话信息，不要公开转发 |

## ✏️ 课后练习

找一个学校或软件官方网站，写出它的完整域名；再找一个搜索结果中的相似域名，比较拼写和来源。
