# 第 3 章：请求与响应 — 网页访问是一来一回的对话

## 📋 本章概览

| 项目 | 内容 |
|:---|:---|
| 学习时长 | 10 分钟 |
| 核心概念 | HTTP、HTTPS、GET、POST、状态码、请求头、响应体 |
| 核心比喻 | 前台填单与回执 |
| 实践任务 | 读懂一次公开 GET 请求 |

浏览器发送请求，服务器返回响应。你不需要立刻写代码，但理解这来一回能帮助你判断问题出在哪里。

## 把网页看成一次对话

打开网页时，浏览器不是一次性收到一张完整的“图片”。它会先请求 HTML，再根据 HTML 中发现的线索继续请求样式、脚本、图片和数据。服务器对每次请求返回结果，这些结果共同组成你眼前的页面。理解这个过程后，状态码就不再是吓人的数字，而是帮助你定位问题的路标。

观察请求时要把“发生了什么”和“我猜原因是什么”分开记录。例如看到 404，能确定的是某个地址没有找到资源；至于链接写错、资源被删除还是版本切换，还需要继续核对。先记证据、后下结论，是这一章最重要的排错习惯。

## 3.1 常见请求方法

`GET` 通常用于请求页面或数据；`POST` 通常用于提交内容。方法只是线索，具体行为还要看网站设计。不要在不理解的情况下重复提交表单或刷新付费操作页面。

## 3.2 认识状态码

| 状态码范围 | 生活化理解 | 常见例子 |
|:---|:---|:---|
| 2xx | 前台办好了 | 200 |
| 3xx | 请去另一个窗口 | 301、302 |
| 4xx | 你的请求需要修正或没有权限 | 401、403、404 |
| 5xx | 对方窗口处理失败 | 500、503 |

状态码是线索，不是完整结论。一个页面可能整体显示成功，但其中图片或脚本请求失败。

## 3.3 请求和响应里有什么

请求可能包含地址、方法、请求头和提交内容；响应可能包含状态码、响应头和正文。请求头可能包含 Cookie、Authorization 等敏感信息，不要把它们复制到群聊或公开 Issue。

## ✅ 验证步骤

打开一个公开网页的开发者工具，在 Network 中刷新页面，找到一个文档或图片请求，记录方法、状态码、类型、大小和耗时；不要记录 Cookie 或 Authorization。

## ❌ 常见情况

| 现象 | 先判断什么 |
|:---|:---|
| 404 | 地址或资源路径可能不存在 |
| 403 | 可能需要权限，不代表可以尝试绕过 |
| 500 | 服务端处理失败，先等待或联系站点维护者 |
| 页面能看但图片不显示 | 检查图片请求是否失败 |

## 📝 本章总结

- 请求是浏览器提出的问题，响应是服务器返回的结果。
- 状态码帮助定位范围，不是让你盲目重试的按钮。
- 请求头和响应内容可能含有隐私，观察时也要保护它们。

## ✏️ 课后练习

找一个公开网页中的 `200` 请求和一个不存在的 `404` 请求，分别写出它们的地址、类型和状态码，并解释差异。
